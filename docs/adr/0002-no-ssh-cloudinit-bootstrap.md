# Exits bootstrap via cloud-init user-data; no SSH, ever

The Exit is configured entirely through EC2 user-data rendered at launch time: both WireGuard keypairs are generated locally, the server config (with the client's public key), IP forwarding, NAT masquerade, and the dead-man's switch are all baked into the launch request. No SSH keypair is created and port 22 is never opened — the security group allows only UDP 51820. Alternatives were SSH bootstrap (easier interactive debugging, but adds key management, an SSH dependency, and attack surface) and prebaked AMIs (fast boot, but would need copying to ~30 regions, killing the country picker). Consequence: user-data bugs can't be debugged by shelling in — use the EC2 serial console / instance screenshot during development.
